Inside accuCad: How the Prototype Works

A thorough first-person technical walkthrough of the accuCad codebase: controllers, direction-cosine matrices, chorded clicks, and snapping.

TentativePointHandler: 50ms Chord Snap & 3-Axis Mini-Jack

The Controller & 50ms Chord Loop

In accuCad, I built BaseController.js as the central coordinator. It holds the element registry (this.cadElements), the floating origin (this.origin = [0, 0, 0]), the active drawing orientation (this.rotationMatrix as a 3×3 direction cosine matrix), and the registered tool instances (rectangle, arc, path, curve, circle, capsule, move, rotate, scale, delete).

Input flows through EventHandlers.js. When the mouse moves, screen pixels are unprojected into a 3D ray by GeneratePoint.generate(). The ray's intersection with the active drawing plane yields a raw point. That point feeds directly into AccuDrawLogic.onMotion(), which evaluates active axis locks and directional deltas. Finally, getConstrainedPoint() calculates the definitive 3D coordinate and forwards it to the active command's onPoint({ mode: 'hover' }) handler. When explicit orientation changes occur, the engine supports both Rotate Quick (RQ)—which preserves the current plane normal and rotates X toward a picked reference point—and Rotate Axes (RA), which allows three arbitrary points to define an origin, primary axis, and planar orientation deterministically via cross-product math.

Event Handling Chorded Clicks & The 4-Tier Escape Cascade
  • Perpendicular Projection (Default Snap): Snapping to an off-axis point drops a 90° normal onto the locked trajectory in 3D world space, strictly view-independent with zero view distortion.
  • Nearest Snap ('N') Ray-Curve Intersection: Solves quadratic ray-arc intersections and resolves multi-root ambiguity using cursor proximity.
  • The 4-Tier Escape Cascade: Escape 1 cancels active typing; Escape 2 unlocks the active axis; Escape 3 releases tentative snap; Escape 4 resets the active tool.

AccuDrawLogic: Relative Vectors & Smart Lock

I wrote AccuDrawLogic.js to manage the mathematics of the floating frame. It doesn't calculate in absolute world space. Instead, it computes the delta vector between the cursor and this.origin, then projects that vector against the orientation matrix's basis vectors: lx = delta · X_axis, ly = delta · Y_axis, and lz = delta · Z_axis. In polar mode, it computes distance √(lx² + ly²) and angle atan2(ly, lx) * 180 / π.

My Smart Focus logic handles intent dynamically: as the user moves the mouse freely, onMotion continuously compares |lx| against |ly|. If the mouse pulls more strongly horizontally, the X coordinate receives focus; if it pulls vertically, Y receives focus. When you start typing a number, typingMouseAnchor captures the initial cursor coordinate. If you then deliberately drag the mouse along the perpendicular axis past a threshold, the system automatically commits the typed number and shifts active focus to the other axis.

Constraint Logic Smart Lock (L) & Distance Memory Indexing
  • Smart Lock (L): Evaluates |lx| vs |ly| and locks the subordinate coordinate to 0, or locks polar angles.
  • Screen-Space Hysteresis: Tolerance is evaluated in screen pixels rather than model units, ensuring uniform tactile pull across all zoom levels.
  • Breaking Free: Tapping 'L' while indexed disengages sticky distance memory so drafters can slide to nearby dimensions without snapping backward.

A vital mathematical distinction in AccuDraw is how locked axes interact with snapped elements. When a draftsperson has an axis or angle locked and snaps to an off-axis vertex, the engine performs Model-Space Perpendicular Projection: $\vec{P}_{\text{constrained}} = \vec{Origin} + ((\vec{P}_{\text{snap}} - \vec{Origin}) \cdot \hat{u}) \hat{u}$. This projection completely ignores the camera view direction—it is calculated purely against the 3D vector basis of the constraint line in model space.

TentativePointHandler: 3D Raycasting & 2D Screen Picking

In TentativePointHandler.js, we implemented precision snapping with strict Active Plane Discipline. In early CAD, draftspersons were plagued by passive snap engines that aggressively jumped the working plane onto background geometry simply because the cursor hovered over an unrelated element. In our engine, free cursor motion stays strictly coplanar with the active working plane. Snapping to a 3D feature is an intentional gesture executed via the 50ms two-button chord or Ctrl hover. Crucially, tentative snapping does NOT move the compass origin on its own—it strictly translates when the drafter explicitly presses O (or G on the home row), leaving the construction plane orientation untouched.

This intentional discipline extends into element manipulation and drawing continuity through two independent settings: Floating Origin (advancing the origin to each placed data point) and Context Sensitivity (automatically rotating the compass axes to match newly placed geometry). When drafting orthogonal walls or grids, drafters often disable context sensitivity so the compass remains locked to orthogonal coordinates while the origin continues to float.

Visual Cues The Mini-Jack & Z-Plane Projection Guides
  • Non-Destructive Snap: Candidate vertex snapping never alters the origin until explicitly committed.
  • Set Origin (O / G): Translates the origin without rotating compass orientation.
  • The Mini-Jack: Renders a 3-axis mini-jack at the projected world coordinate with a dashed perpendicular drop-line to the active plane.

Drawing Commands & Camera Oscillation

The tool commands follow a clean lifecycle. In DrawPathCommand.js, vertices are placed with a radius property, allowing continuous lines with real-time rounded corner fillets calculated via RoundingUtils3D.getRoundingData. In DrawRectangleCommand.js, rectangles are placed with arbitrary 3D orientation matrices rather than simple screen-aligned boxes, allowing boxes and slabs to be built across any face.

For camera control, ViewManipulator.js handles smooth panning and rotation, while CameraOrbitAnimator.js provides gentle, continuous motion parallax oscillation around the target point. A key detail in CameraOrbitAnimator is its self-healing re-anchoring: if the user pans or rotates while oscillation is running, the math recalculates the phase offset without resetting the camera violently.
