Self-Replicating Blueprint Architecture

Luno Loop & Self-Replication

The plan is the application: how CAD Plan self-replicates, tests its own geometry, and evolves through surgical LLM collaboration.

The Living, Self-Replicating Blueprint

In traditional software engineering, developers build monolithic applications and write separate, static documentation that rots within months. In our architecture, the document is the primary deliverable, not a secondary byproduct. Notice how the application ecosystem is structured: we have decomposed the monolithic CAD suite into focused, testable sub-views (CompassApp, KeyCommandApp, TouchController, and accuCad), unified by the shared Library hub. And CadPlan is the living master orchestrator that embeds, audits, and runs all of these instruments side-by-side in real time without nested iframes.

More importantly, it is built to self-replicate and improve itself using Luno. Because every section, demo, and paragraph is an independent static method or clean HTML block, an LLM can inspect, refine, or add new capabilities with surgical precision. When you start a fresh conversation with an AI, you don't need to paste 600,000 tokens of chat history. You simply bundle CadPlan, and the AI immediately receives 100% of the project's history, philosophy, prototype audits, and live demos in a lean payload.

Methodology Why The Plan Is The Application
  • 1. CompassApp: In-process 3D Squircle Studio isolating compass geometry, direction cosines, and morphing without dialog clutter.
  • 2. KeyCommandApp: Standalone Keystroke Engine testing single-stroke commands without Enter and numerical range bindings.
  • 3. TouchController: Standalone Mobile WebRTC Glass Deck for two-handed analog parameter scrubbing over local Wi-Fi.
  • 4. accuCad: The unified CAD workstation combining snapping, solids, curves, and tool settings panels.
  • 5. Library: Central shared dependency repository (DomBasics, ThreeJSLoader, UITools).
  • 6. CadPlan: The Living Master Specification that embeds, tests, and documents every tool natively!

Surgical Patching & Instant Iteration

The engine driving this rapid evolution is Luno's copy-paste loop. Luno runs on a local Node.js server, stores projects in IndexedDB or direct disk files, and provides an isolated preview environment where the application updates live.

The workflow is simple: I copy a prompt or code bundle from Luno's Outbox, paste it to an LLM, copy the AI's response, and tap "Paste from Chatbot" in Luno. Luno parses the response in browser client JavaScript using the HTML Container Protocol, extracting surgical method patches (<script data-method="..." data-action="patch">) and HTML template blocks (<template data-block="..." data-action="patch">).

Protocol Architecture Surgical Method Patch Containers

The HTML Container Protocol in Action:
• Surgical Class Method Patches: Instead of re-streaming 50KB files, the LLM outputs only the modified method.
• Client-Side AST Merging: Luno's LunoClassPatcher parses the target file's AST using Acorn, splices the updated method into place, verifies syntax, and saves the file directly to disk.
• Instant Hot-Reload: The application reloads in milliseconds, allowing continuous real-time iteration without build pipeline delays.

This workflow eliminates the token bloat and context fatigue that plague traditional AI programming. A single developer, equipped with domain experience and supported by an agentic AI partner through Luno, can build, audit, and evolve complex CAD software at unprecedented speed.

The Genetic Mutation & Cross-Thread Recombination Protocol

Here is where this software architecture enters a truly revolutionary frontier: the document itself can copy itself, mutate inside an AI conversation, and recombine seamlessly with other mutated copies. In traditional development, collaborating across experimental branches requires complex Git merges, resolving conflicting lines of code, and risking broken builds. With CadPlan and Luno, software evolution mirrors biological reproduction. Because the living specification is composed of modular, addressable components—each paragraph, mathematical calculator, and Three.js viewport being an isolated method or template block—you can copy the whole organism into an LLM, instruct the model to explore a mutation (such as inventing a new clockwork steampunk compass reticle or optimizing ray-curve snapping), and test that mutated branch independently.

Evolutionary Loop Fork, Mutate, and Recombine via LLM Context
  • 1. Living State Extraction: The author captures the active organism (code, DOM XPaths, user directives) in a lean Outbox payload.
  • 2. Divergent Mutation: Fork the payload across parallel AI chats (e.g., Thread A builds Rust Wasm bindings, Thread B invents two-handed mobile gestures).
  • 3. Granular AST Containerization: Each thread outputs isolated patches using the HTML container protocol (<script data-method="...">).
  • 4. Recombination Synthesis: Feed both patch logs into an LLM context to synthesize a conflict-free hybrid.
  • 5. Instant In-Situ Compilation: Luno splices the reconciled methods into the runtime heap—completing the evolutionary loop!

When you are ready to bring those experimental threads together, you don't fight merge tools. You simply take the surgical container outputs from both threads, paste them into a large context window, and say: "Merge these two capabilities into one unified system." The LLM evaluates the AST differences, verifies that neither mutation breaks the core direction-cosine or snapping invariants, and produces a single, reconciled patch bundle. With one click of "Paste from Chatbot", Luno splices the unified genetic code into the live files in browser memory, and the evolved application boots instantly without reload friction.
