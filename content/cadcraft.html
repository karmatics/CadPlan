The ArtCraft Phenomenon & CADCraft Opportunity

Among tools like PhotoCraft, VectorCraft, and FilmCraft, the flagship engineering tool is CADCraft (v0.7.0, hosted at github.com/storytold/cadcraft and getartcraft.com). Because this specification is mathematically rigorous and complete, a modern AI agent can implement these hooks into CADCraft overnight, leaving only verification and testing for the maintainers.

PointMod.rs: The Coordinate Filter Interception Point

Inside cadcraft-engine/src/pointmod.rs, CADCraft implements standard AutoCAD point modifiers. In AutoCAD, point modifiers allow users to filter incoming points (e.g., typing .x to lock the X coordinate of a reference vertex, or engaging Ortho mode with F8 to restrict movement to horizontal or vertical axes).

In CADCraft's source code, Session::point_mods stores an active stack of Frame enums representing active .X, .Y, FROM, or M2P modifiers. CompassDraw bypasses this friction by maintaining a live 3D floating orientation frame (Mat3): single-key shortcuts (X, Y, Z, L) lock dimensions instantaneously without prompting, passing resolved coordinates directly to the command.

Polyline Arc Segments & The Universal Bulge Factor

Our inspection of CADCraft's crates/engine/src/cmd/pline_opts.rs revealed how native polyline arc segments are stored. CADCraft uses the universal CAD bulge factor: cadcraft_geom::arc_to_bulge and bulge_to_arc.

In AutoCAD and CADCraft's LwPolyline, every vertex is stored as (x, y, bulge). When bulge = 0.0, the segment is a straight line. When bulge != 0.0, it encodes a circular arc whose included sweep angle is $\theta = 4 \arctan(\text{bulge})$ (positive for counter-clockwise, negative for clockwise). This is mathematically elegant: a single scalar encodes whether a segment is straight or an arc without allocating separate entities.

Arc Representation DXF Bulge tan(θ/4) vs. SmartLine Continuous Fillets
  • Definition: bulge = tan(θ / 4) = (2 * height) / chord_length
  • Exact Geometry: Lossless round-tripping through DXF and binary DWG.
  • Zero Allocation: A polyline with 50 arcs and lines is a single contiguous array of (x, y, bulge) tuples.
  • SmartLine Parity: When SmartLine transitions from a line to an arc, it simply computes the tangent bulge and writes it to the prior vertex.

PlineM & Mat4::ocs 3D Plane Extrusion Pipeline

To wire CompassDraw into CADCraft, we must understand how AutoCAD and CADCraft represent 3D geometry. CADCraft adopts AutoCAD's historical coordinate hierarchy:

1. WCS (World Coordinate System): The immutable 3D Cartesian frame $(X_w, Y_w, Z_w)$ shared by all entities.
2. UCS (User Coordinate System): A movable 3D frame with an origin $\vec{O}_{ucs}$ and orientation matrix.
3. OCS / ECS (Object/Entity Coordinate System): An ingenious 2.5D storage optimization. Instead of storing bloated 3D $(x, y, z)$ coordinates for every node of a planar entity (LWPOLYLINE, CIRCLE, ARC, HATCH), CADCraft stores an Extrusion Normal Vector $\vec{N} = (N_x, N_y, N_z)$, an Elevation scalar $Z_e$, and compact 2D $(u, v)$ coordinates on that plane.
4. DCS (Display Coordinate System): The viewport projection space (orthographic or perspective) where 3D world geometry is mapped to 2D screen pixels.

To convert between 2D OCS $(u, v)$ and 3D WCS $(X_w, Y_w, Z_w)$, CADCraft implements AutoCAD's Arbitrary Axis Algorithm in crates/geom/src/mat.rs via Mat4::ocs(normal: Vec3). When CompassDraw is active, our ThreeAxes $[\vec{X}_c, \vec{Y}_c, \vec{Z}_c]$ sets $\vec{Z}_c = \vec{N}$. Every 3D point $\vec{P}$ resolved by AccuDraw is projected into CADCraft's OCS plane using $u = (\vec{P} - \vec{O}_w) \cdot \vec{A}_x$ and $v = (\vec{P} - \vec{O}_w) \cdot \vec{A}_y$. CADCraft saves the entity as a native LwPolyline, and standard AutoCAD renders the 3D angled geometry losslessly.

Rust Pipeline PlineM Machine & Mat4::ocs Normal Basis
  • Arbitrary Axis Algorithm: Derives an orthonormal 2D basis $[ax, ay]$ perpendicular to any arbitrary 3D extrusion normal $N$.
  • AccuDraw Alignment: Sets $Z_c = N$, projecting 3D cursor coordinates into planar $(u, v)$ offsets.
  • Native Compatibility: Serializes directly as AutoCAD LWPOLYLINE with zero proprietary schema drift.

The Bi-Directional Dialogue: Making AccuDraw Feel Native to AutoCAD

To make AccuDraw feel completely native inside an AutoCAD runtime like CADCraft, we must solve a profound interaction conflict. Historically, AutoCAD is a prompt-driven engine: tools like LINE and PLINE sit in a passive waiting loop, printing prompts like 'Specify next point or [Arc/Close/Undo]:' and expecting typed coordinates or keywords followed by Enter. AccuDraw is a kinetic, event-driven HUD: it floats an origin at the cursor, locks axes on the fly, and computes relative vector displacements in real time. The breakthrough in our architecture is making CADCraft's command prompt a reactive event listener for AccuDraw.

Runtime Architecture The Reactive AutoCAD Prompt ↔ AccuDraw Contract
  • Prompt Awakening: When AutoCAD prompts for Accept::POINT, CompassDraw wakes up and places the squircle compass at the cursor.
  • Single-Stroke Keyword Latching: If prompt keywords contain ["Arc", "Close", "Undo"], CompassDraw binds A, C, and U directly to those branches without Enter.
  • Undo Synchronization: When AutoCAD triggers undo, CompassDraw pops its SavedState stack in lockstep, returning the compass origin to the prior vertex.

On the data side, we keep the coordinate system clean and high-level. Tools, scripts, and AI coding agents should never have to manually write out matrix equations to place a line or arc. In compassdraw-core, we define a universal CoordinateBridge operating on pure [f64; 3] arrays, providing instantaneous bidirectional translations between World Coordinates (WCS), Local Compass Deltas $(dx, dy, dz)$, AutoCAD Planar Object Coordinates (OCS), and Screen Pixels (DCS).

Mathematical Bridge The Universal CoordinateBridge (WCS ↔ Compass ↔ OCS)
  • wcs_to_compass(p_wcs, origin, axes): Converts 3D world coordinates to local deltas $(dx, dy, dz)$.
  • compass_to_wcs(delta, origin, axes): Converts local deltas back to world space $(X, Y, Z)$.
  • wcs_to_ocs(p_wcs, normal): Maps 3D world vertices to AutoCAD 2D planar $(u, v)$ plus elevation.

Engineering Hazards: The 4 Tricky Traps Where CAD Integrations Fail

When building a precision 3D CAD engine on top of AutoCAD data structures, simple vector math often fails at edge cases. Because CAD systems rely on zero-tolerance geometric invariants, minor mathematical discontinuities cause catastrophic visual glitches: polylines suddenly rotating 90 degrees when tilted past vertical, infinite tangents on circular arcs, and snap cursors jumping into empty background space. In this section, we document the four most dangerous engineering hazards discovered during our code audit of CADCraft and AutoCAD DXF specifications, and provide the exact algorithms used by compassdraw-core to resolve them.

Singularity Trap Hazard 1: The OCS Arbitrary Axis Discontinuity Jump

AutoCAD switches reference cross-vectors when $|N_x| < 1/64$ and $|N_y| < 1/64$. Crossing this boundary causes $\vec{A}_x$ to abruptly jump 90°, rotating polylines in naive importers. compassdraw-core measures the phase angle $\phi = \text{atan2}(\vec{X}_c \cdot \vec{A}_y, \vec{X}_c \cdot \vec{A}_x)$ and rotates 2D vertices by $-\phi$ before saving, keeping the 3D geometry completely stationary.

The second hazard occurs during snapping in 3D perspective views. In 2D drafting, any two non-parallel lines intersect at a point. In 3D space, two line entities almost never intersect—they are skew lines separated by an arbitrary 3D distance vector. On a 2D monitor, their visual screen projections cross. If an interactive snap engine naively tests for raycast intersections, it latches onto one of the background vertices, violently pulling the AccuDraw compass off its active construction plane.

3D Projection Trap Hazard 2: 3D Skew Lines vs. Apparent 2D Crossings

Under Active Plane Discipline, candidate skew lines are projected onto the user's active construction plane along the plane normal $\vec{Z}_c$. The intersection is solved strictly in the 2D plane coordinate system, ensuring that snapping to apparent crossings never alters the user's working depth.

Mathematical Limit Hazard 3: The 360° Bulge Singularity & Inflection Noise

As arc sweep approaches 360°, $\text{bulge} = \tan(\theta/4) \to \infty$. A full circle cannot be stored as a single polyline vertex. SmartLine automatically splits sweeps over 359.9° into two 180° segments ($\text{bulge}=1.0$), and enforces a $10^{-5}$ deadband to prevent hand micro-tremors from generating tiny arc bulges on straight lines.

Display Scaling Hazard 4: Retina & High-DPI Snap Aperture Scaling

A fixed 10-pixel snap aperture becomes an ultra-tiny 5-pixel target on Retina and 4K displays. compassdraw-core scales screen-space picking thresholds by window.devicePixelRatio, ensuring uniform physical picking tolerances across all displays.

EntityStore: Copy-on-Write Database & Zero-Cost Undo Snapshots

Our inspection of cadcraft-doc/src/store.rs confirms CADCraft's copy-on-write memory model (EntityStore). In traditional CAD databases, undo/redo stacks require heavy deep-cloning of entire drawing trees or complex reverse-delta journals that easily desynchronize after topological edits.

In CADCraft, entities are immutable records indexed by generational handles (Handle). Taking an undo snapshot is a cheap pointer clone of the EntityStore. Modifying an entity creates a localized copy-on-write branch. This provides instant multi-level undo/redo during rapid CompassDraw drafting sessions with zero garbage collection overhead.

Memory Architecture EntityStore Generational Handles & CoW Snapshots
  • Handle(u32): Eliminates dangling pointers and protects against iterator invalidation.
  • Copy-on-Write: Whole-drawing states clone in sub-microsecond time as pointer copies.
  • Transaction Safety: Tool commands commit clean transactional deltas.

Accept::POINT & The Native Command State Machine

To understand how input is dispatched on the other side, we examine CADCraft's command loop in crates/engine/src/cmd/draw.rs and session.rs. Every interactive tool implements the Interactive trait, declaring an input state machine driven by Prompt. When a user clicks the mouse, the engine dispatches Input::Point(Vec2). The command machine updates its internal vertex buffer and commits changes to the document database.

Our PointInterceptor hook sits in crates/engine/src/session.rs immediately above this event loop. Window events unproject 2D cursor coordinates into a 3D ray in WCS. PointInterceptor::filter_point tests the ray against CompassDraw's active construction plane, evaluates active locks (X, Y, Z, Dist, Angle), and calculates snapping proximity. If constrained, it transforms the 3D coordinate into CADCraft's OCS plane (u, v) and hands Input::Point(Vec2::new(u, v)) to the command step, satisfying Accept::POINT on the very first frame without modal prompts.

  • 2. Camera unprojects into 3D ray in World Space.
  • 3. PointInterceptor applies AccuDraw deltas and locks.
  • 4. Coordinates are projected into CADCraft OCS $(u, v)$ and dispatched.

The Levenberg-Marquardt Solver in cadcraft-constraints

A notable discovery in the CADCraft codebase is cadcraft-constraints. The crate includes lm.rs (a Levenberg-Marquardt non-linear least-squares solver) and dof.rs (a Degrees-of-Freedom analyzer). This shows CADCraft is already laying the foundation for parametric constraint solving.

Inside CADCraft's crates/constraints/src/lm.rs, the Levenberg-Marquardt solver minimizes non-linear geometric residuals using a damped Gauss-Newton step: $\Delta x = -W^{-1} J^T (J W^{-1} J^T + \mu I)^{-1} r$ with finite-difference Jacobians. Under-constrained drawings move as little as possible, and recently placed vertices are heavily weighted. This creates a direct synergy with CompassDraw: when a user snaps an AccuDraw parallel, perpendicular, or distance lock, CompassDraw resolves the instantaneous 3D point for the command loop, and simultaneously posts a residual constraint to cadcraft-constraints for persistent parametric updates.

Constraint Math Degrees of Freedom (dof.rs) & LM Non-Linear Solver

  • dof.rs: Tracks unconstrained degrees of freedom across topological vertices.
  • Synergy with CompassDraw: Real-time kinetic locks convert directly into persistent parametric rules.

The Clean Tack-On Specification: Zero Upstream Fork Drift

The primary architectural requirement for the upstream integration is maintaining zero fork drift: CADCraft's command loop, document schema, and file parsers must remain completely unmodified. CompassDraw sits in cadcraft-engine as an optional input filter. When a user is in classic AutoCAD mode, raw mouse events flow directly into pointmod.rs as normal. But when CompassDraw is engaged, it intercepts mouse coordinates and keyboard strokes before CADCraft's prompt state machine can enter a modal waiting state.

To achieve this, our AI agents will submit a clean pull request implementing the PointInterceptor trait in cadcraft-engine/src/interceptor.rs. In session.rs, before Session::step evaluates input modifiers, it checks interceptor.filter_point(...). If the compass has an active axis lock, tentative point, or distance constraint, it returns the resolved coordinate. The command receives a valid coordinate satisfying Accept::POINT on the first click. Single-keystroke commands (T, F, S, V, L, Space) return true from handle_key(...), intercepting the keystroke before it can clutter the AutoCAD command-line prompt buffer.

  • PointInterceptor::filter_point: Resolves raw viewport raycasts into constrained 3D/2D coordinates.
  • PointInterceptor::handle_key_down: Captures single-stroke shortcuts without waiting for Enter.
