The 4-Layer Headless Geometric Kernel

Our working accuCad prototype proved the interaction ergonomics, but coupled the mathematics directly to Three.js scene objects. For the production engine, the most important architectural mandate is decoupling: the geometric and constraint kernel must have zero rendering dependencies.

System Boundary The Clean 4-Layer Boundary
  • Layer 1: Pure Geometry & Constraint Kernel (compassdraw-core): Headless, pure mathematical functions operating on raw numbers or typed Float64Arrays ([x, y, z]). Manages AccuDraw direction cosines, floating origin translation, and ray-plane intersections with zero WebGL/DOM dependencies in WebAssembly or native Rust CLI.
  • Layer 2: Command & Tool Pipeline: Manages active drawing commands, single-stroke hierarchical shortcuts (KeyCommandHandler without Enter), SmartLine multi-segment continuous chaining (lines, arcs, fillets), and 50ms chorded tentative snapping.
  • Layer 3: Render Adapter: Browser uses Three.js WebGL with Line2 thick anti-aliased wireframes; native desktop connects to cadcraft-render and wgpu vertex/index buffers.
  • Layer 4: UI & Ergonomics Shell: Morphing squircle compass, glowing cursor caret, coordinate readouts, and P2P dual-trackpad TouchController over low-latency WebRTC.

By establishing this 4-layer boundary, our core drafting, constraint, and SmartLine mathematics can run anywhere with 100% interoperability:

1. CADCraft Direct Entity Mapping: A continuous path drawn in accuCad maps 1:1 into CADCraft's LwPolyline with PolyVertex { point, bulge: tan(θ/4) } through RoundingUtils3D.arcToBulge.

2. Bentley iTwin Parity: AccuDraw's 3D orientation matrices translate directly into ThreeAxes, while SmartKeyin eliminates 100% of negative coordinate typing across viewports.

3. Zero UI / DOM Pollution: The geometric solver runs headless in WebAssembly, background Web Workers, or Node.js server scripts without touching Three.js objects or browser DOM elements.

Cross-Platform Windowing: Native wgpu & The 2D/3D Unified Viewport

A critical decision in this architecture is resolving the relationship between 2D drafting and 3D modeling. The foundational mistake CAD vendors made in the 1980s was maintaining separate 2D drafting engines and 3D solid modelers. In our architecture, 2D is not a separate engine, nor is it an SVG viewport—it is simply a 3D orthographic camera locked to a 3D construction plane at $Z = 0$. When a drafter works in "Classic 2D Mode", the camera is locked into top orthographic alignment. The AccuDraw compass sits on the Top plane basis, emitting standard 2D coordinates (Vec2(x, y)) directly into CADCraft commands (LINE, CIRCLE, OFFSET, TRIM). When the user engages 3D, the camera transitions to perspective orbit, the compass tilts to Front (F), Side (S), or Surface Normal (Q), and CADCraft's Mat4::ocs maps the planar polyline vertices (PolyVertex { point, bulge }) into 3D world space. There is only one mathematical pipeline.

Windowing & Pipeline Matrix The Desktop wgpu & Web Wasm Windowing Stack
  • 1. Native Desktop Binaries (macOS, Windows, Linux): Windowing & event loop via winit; UI chrome via cadcraft-ui-egui; GPU renderer via native wgpu (Metal/DX12/Vulkan); custom 3D AccuDraw pass in cadcraft-render drawing squircle boundary and Mini-Jack.
  • 2. Browser WebAssembly: Canvas runner via eframe WebGPU with WebGL2 fallback (?webgl); kernel execution via compassdraw-core compiled directly to Wasm in-process.
  • 3. WebViews, Electron & Three.js Studio Mode: Embedded host bridge using CADCraft's apps/cadcraft-web/src/host.rs with ?host=parent&webgl; Three.js overlay rendering PBR clearcoats and studio lighting.
  • 4. Headless SVG Export: SVG is reserved exclusively for vector plotting and UI badges, never as the interactive viewport engine.

By decoupling windowing and rendering through this matrix, AI coding agents can develop and maintain both native and web targets without branching business logic. The compassdraw-core crate remains completely headless (no_std compatible pure Rust). On native desktop systems, winit and wgpu deliver high-frame-rate, sub-millisecond drawing response with minimal memory footprint. In browser and Electron environments, the same coordinate constraint logic drives WebGL/Three.js viewports and pairs seamlessly with our WebRTC mobile TouchController over local Wi-Fi. The draftsperson gets identical single-stroke ergonomics on any machine.

Tapping into Solid Open-Source CAD Engines

We do not need to reinvent basic low-level geometry algorithms from scratch. A major part of our strategy is evaluating and tapping into existing high-quality open-source CAD and geometric kernels (such as OpenCascade.js, ManifoldCAD, or modern WebAssembly boundary-representation libraries).

Our unique competitive advantage is the interaction engine: the AccuDraw floating compass, the chorded tentative snapping, the on-curve pen replacement, and the multi-touch phone controller. By layering my proven interaction paradigm on top of solid open-source geometric backends, we can achieve high-end CAD capability in record time.
