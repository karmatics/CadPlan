Rethinking Prompt Engineering: The Living Specification Loop

This architecture fundamentally rethinks the entire concept of prompt engineering. Traditional prompt engineering is a brittle exercise in writing repetitive chat prompts, hoping an LLM understands your architecture from memory. Our approach is vastly superior: the running application IS the prompt, and the prompt IS the running application. The human author interacts directly with the live document. You read the technical text, test the interactive laboratories, and use Aardvark to attach living directives and voice notes directly to specific paragraphs, canvas stages, or DOM elements. The system packages the entire state—including exact DOM XPath locators, code contexts, and author ideas—into an immense, mathematically grounded prompt bundle.

The next major milestone is Deep Luno Interconnection with Universal Free-Form Comments. Instead of keeping document notes isolated in local dialogs, any comment, sketch, or voice directive attached to any paragraph, diagram, or canvas will push directly into Luno's Outbox. Luno acts as an in-process continuous development engine: the human author tours the living specification, attaches free-form thoughts anywhere across the DOM, and with one tap dispatches an aggregated prompt bundle to the AI. The AI streams back surgical class method and HTML template patches, and Luno compiles them straight into local files in real time.

AI Methodology The Human-in-the-Loop Living Specification Cycle
  • 1. Interactive Review: The inventor reads the technical dossier and tests live interactive viewports.
  • 2. Universal Annotation: Aardvark pins directives directly to specific paragraphs, diagrams, or DOM nodes.
  • 3. Automated Outbox Compilation: CadPlan compiles all notes, XPaths, and code contexts into a single payload.
  • 4. AI Spec Refinement: The LLM refines the architectural specification, resolving edge cases and updating chapters.
  • 5. Client-Side Splicing: Luno merges surgical class method and HTML template patches with zero token waste.

The Anti-Redundancy Mandate: Single Source of Truth & Modular Instruments

A core architectural invariant of this codebase is absolute non-redundancy. In many software projects, developers create simplified mock-ups or duplicate parallel versions of core algorithms for individual demos—such as writing an ad-hoc 3D compass in a demo component that reorients on Q using fabricated math, rather than running the authentic AccuDraw compass from accuCad. This is strictly forbidden. There is only one authentic accuCad. Rather than spawning duplicate implementations, our architecture requires that every demonstration, lab, and viewport draws directly from the exact same modular source files (SquircleArc.js, AccuDrawLogic.js, RoundingUtils3D.js, KeyCommandHandler.js). If a component needs to show a specialized subset—such as an isolated view of the compass or an on-curve spline—it must configure and render that subset using the original production classes.

This modular reusability extends across the entire ecosystem. Components such as ColorPicker.js (with its RYB hue ring and barycentric tint/shade triangle) and SliderControl.js (with direct numerical entry and inertia wheels) are used inside accuCad, but they are built as general-purpose instruments. Because they are modular, we can instantiate and test them independently anywhere on the web, embed them throughout documentation chapters, and wire them directly to our low-latency mobile TouchController trackpad deck over local Wi-Fi. Every tool stands on its own, shares the single source of truth, and eliminates duplicate code maintenance.

Engineering Invariant The Anti-Redundancy & Reusability Mandate
  • Single Source of Truth: Never create duplicate or mock versions of core CAD math (SquircleArc, AccuDraw, RoundingUtils3D). Every lab or demonstration mounts the authentic modular class with tailored options.
  • Modular Component Hierarchy: Instruments like ColorPicker and SliderControl are general-purpose building blocks shared across CAD, UI, and mobile touch surfaces. Viewports can isolate a specific subsystem while maintaining 100% mathematical fidelity.
  • True Outbox Integration: Actions labeled 'Send to Outbox' communicate directly with Luno's OutboxQueue across iframes and windows rather than simply dumping text to the clipboard.
